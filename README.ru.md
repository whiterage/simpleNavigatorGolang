# Simple Navigator

Алгоритмы на графах, написанные с нуля на Go, с интерактивным терминальным интерфейсом.

Никаких graph-библиотек: сам граф, структуры для обхода (стек и очередь) и все перечисленные ниже
алгоритмы написаны вручную и покрыты тестами.

[English version](README.md)

---

## Алгоритмы

| Задача | Алгоритм | Сложность |
|---|---|---|
| Обход | Поиск в ширину | O(V²) |
| Обход | Поиск в глубину | O(V²) |
| Кратчайший путь между двумя вершинами | Дейкстра | O(V²) |
| Кратчайшие пути между всеми вершинами | Флойд–Уоршелл | O(V³) |
| Минимальное остовное дерево | Прим | O(V³) |
| Коммивояжёр | Муравьиный алгоритм | O(iters · ants · V²) |
| Коммивояжёр | Ближайший сосед (жадный) | O(V²) |
| Коммивояжёр | Полный перебор (точный) | O(V!) |

Сложности указаны для матрицы смежности, которая используется во всём проекте: Дейкстра и Прим
выбирают следующую вершину линейным проходом, а не через кучу — на плотных матрицах это выгоднее.

BFS и DFS построены на собственных пакетах `queue` и `stack`, а не на слайсах, поэтому код обхода
читается так же, как алгоритм в учебнике.

## Быстрый старт

Нужен Go 1.22 или новее.

```bash
git clone https://github.com/whiterage/simpleNavigatorGolang.git
cd simpleNavigatorGolang
make run
```

Остальные цели:

```bash
make build          # собрать ./bin/simple_navigator
make test           # запустить все тесты
make test-coverage  # тесты с покрытием
make fmt vet        # форматирование и vet
make clean          # удалить артефакты сборки
```

## Работа с приложением

Приложение открывает меню, пункты выбираются стрелками. Начните с **«Загрузить граф из файла»** —
остальные пункты недоступны, пока граф не загружен.

```
╭──────────────────────────────────╮
│ Simple Navigator                 │
│ ● граф загружен  assets/tsp_8.txt │
╰──────────────────────────────────╯
  ↑/↓ - navigate / enter - select
  ▸ Загрузить граф из файла
    Обход в ширину (BFS)
    Обход в глубину (DFS)
    Алгоритм Дейкстры
    Алгоритм Флойда-Уоршелла
    Алгоритм Прима
    Задача коммивояжера
    Сравнение алгоритмов TSP
    Выход
```

В [`assets/`](assets) лежат три примера графов:

| Файл | Описание |
|---|---|
| `graph.txt` | 5 вершин, разреженный, часть рёбер односторонние |
| `tsp_4.txt` | 4 вершины, полный — перебор можно проверить вручную |
| `tsp_8.txt` | 8 вершин, полный — интересный случай для сравнения TSP |

Последний пункт меню запускает все три решателя задачи коммивояжёра N раз на загруженном графе и
показывает общее и среднее время каждого — так наглядно видно, как точный алгоритм проигрывает
эвристикам с ростом графа.

## Формат файла с графом

Обычный текстовый файл с квадратной матрицей смежности. Ячейка `i, j` — вес ребра из вершины `i`
в вершину `j`, `0` означает отсутствие ребра. Значения разделяются пробелами, пустые строки
игнорируются.

```
0 1 5 10
1 0 2 4
5 2 0 3
10 4 3 0
```

Вершины нумеруются с 1 — и в API, и в интерфейсе.

## Использование как библиотеки

```go
package main

import (
	"fmt"
	"log"

	"github.com/whiterage/simpleNavigatorGolang/algorithms"
	"github.com/whiterage/simpleNavigatorGolang/graph"
)

func main() {
	g := graph.NewGraph()
	if err := g.LoadFromFile("assets/tsp_8.txt"); err != nil {
		log.Fatal(err)
	}

	algs := algorithms.NewGraphAlgs()

	order, err := algs.BFS(g, 1)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("порядок обхода BFS:", order)

	tour, err := algs.SolveTravelingSalesmanProblem(g)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("маршрут %v, длина %.2f\n", tour.Vertices, tour.Distance)

	if err := g.ExportToDot("graph.dot"); err != nil {
		log.Fatal(err)
	}
}
```

`ExportToDot` пишет файл в формате Graphviz, так что загруженный граф можно отрисовать командой
`dot -Tpng graph.dot -o graph.png`.

### API

**`graph`**

| Метод | Возвращает |
|---|---|
| `NewGraph()` | пустой граф |
| `LoadFromFile(path)` | error — отвергает пустой, неквадратный и нечитаемый ввод |
| `ExportToDot(path)` | error — пишет Graphviz DOT |
| `Matrix()` | защитную копию матрицы смежности |
| `Vertex()` | количество вершин |
| `HasNegativeWeight()` | есть ли отрицательные веса |

**`algorithms`** — методы `GraphAlgs`

| Метод | Возвращает |
|---|---|
| `BFS(g, start)` / `DFS(g, start)` | `[]int` — вершины в порядке обхода |
| `GetShortestPathBetweenVertices(g, from, to)` | `float64` — расстояние |
| `GetShortestPathsBetweenAllVertices(g)` | `[][]float64` — матрицу расстояний |
| `GetLeastSpanningTree(g)` | `[][]float64` — остовное дерево как матрицу смежности |
| `SolveTravelingSalesmanProblem(g)` | `TsmResult` — муравьиный алгоритм |
| `SolveTravelingSalesmanProblemNearestNeighbor(g)` | `TsmResult` — жадный |
| `SolveTravelingSalesmanProblemBruteForce(g)` | `TsmResult` — точный |

`TsmResult` содержит маршрут в `Vertices []int` (начинается и заканчивается одной вершиной) и его
полную длину в `Distance float64`.

**`queue`** и **`stack`** — небольшие контейнеры для `int`: `Push`, `Pop`, `Size`, `IsEmpty`, плюс
`Front`/`Back` у очереди и `Top` у стека.

## Что стоит знать о поведении

- Дейкстра, Флойд–Уоршелл, Прим и решатели TSP отвергают графы с отрицательными весами.
- Полный перебор TSP отказывается работать с графом больше 10 вершин — 10! это уже практический
  потолок.
- Прим возвращает `ErrDisconnectedGraph`, если остовного дерева не существует.
- Муравьиный алгоритм стохастический, поэтому повторные запуски могут давать разные маршруты.
  Он выполняет 500 итераций с `min(V, 200)` муравьями, `alpha = 1.0`, `beta = 2.0`, испарение `0.1`.
